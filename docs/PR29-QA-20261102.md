# PR #29 1차 통합 검증 기록

사용자 요청에 따라 추가 디자인 작업과 반복 검사를 중단한 시점의 기록입니다. **main 병합·배포는 하지 않았습니다. 최종 전체 검사가 모두 통과한 상태는 아닙니다.**

- Supabase 운영 DB·데이터·스키마에 접근하거나 변경하지 않았습니다.

## 최소 수정

1. 채팅 파일만 `rpg-30`으로 남아 있던 혼합 import를 해소하고 전체 모듈을 `rpg-37`로 통일했습니다. 채팅 동작 로직은 변경하지 않았습니다.
2. `scene.js`: 식혜 원샷 게임의 완료 후 컵 정리가 취소 콜백으로 전달되어 투어가 진행되지 않는 문제를 수정했습니다. 완료된 게임만 투어에 기록하고 중도 취소는 기록하지 않습니다.
3. `scene.js`: TV 바로 앞에서 앉으면 이동 도착 이벤트가 발생하지 않아 투어가 완료되지 않는 문제를 수정했습니다. 실제 TV 착석 상태에서 완료를 기록합니다.
4. `style.css`: 높이 501px 이상 화면에서 투어 안내를 조이스틱·양머리 버튼 위로 올렸습니다. 작은 가로 화면의 기존 배치는 유지했습니다.
5. `tests/module-cache.cjs`, `tests/channel-readiness.cjs`, `tests/tour-browser.cjs`와 `npm run test:integration` 추가.

실제 기능 수정은 `scene.js`, `style.css`입니다. `net.js`, `social.js` 및 나머지 기존 JS/HTML 변경은 캐시 번호입니다. `package.json`은 검사 명령 추가, README와 이 파일은 인수인계 기록입니다.

| 검사 | 결과 |

| 최초 통합 `npm test` | 캐시 혼합 수정 후 14종 전체 통과. 아래 투어 연결 수정 전 실행 |

브라우저 환경은 Windows Chrome/Playwright, ANGLE D3D11입니다. 기존 테스트의 SwiftShader 인자를 로컬 실행에서 D3D11로 대체했고, 애플리케이션이나 검사 조건을 우회하지 않았습니다. 실제 서비스 API를 대신하는 로컬 전송과 테스트용 광고·카카오 대체 SDK를 사용했습니다.

14단계 투어 검사는 실제 화면 버튼과 완료 이벤트를 사용합니다. 방 사이의 긴 이동은 테스트용 위치 이동으로 단축했고 온탕·세신 대기 시간을 단축했습니다. 이동 경로·충돌은 별도 144개 경로 검사 및 smoke에서 확인했습니다.

## 남은 실패

```text
page.waitForFunction: Timeout 30000ms exceeded.
    at tests/multiplayer.cjs:97:13
```

대화 수락 후 두 번째 탭의 `window.__mp.group()?.size === 2`를 기다리는 단계입니다. 같은 통합 코드의 앞선 실행에서는 통과했으나 마지막 실행에서는 실패했습니다. 시간 경합인지 연결 회귀인지는 확정하지 않았습니다. 사용자 요청에 따라 추가 수정·재실행을 중단했습니다. **이 실패를 무시하거나 전체 통과로 처리하지 않았습니다.**

## 화면·성능 확인 및 한계

- Chrome 모바일 에뮬레이션 390×844 및 PC 1280×800: 신규 입장, 휴게실, 투어 안내와 조작 버튼 비겹침 확인. 별도 smoke는 320px·태블릿·가로 화면, 걷기·앉기·눕기·인사·간식, 로딩 실패·WebGL 복구 등을 통과했습니다(최초 전체 검사).
- 맨머리·양머리 로딩, 표정 및 포즈 화면 확인. 몸 파묻힘·옷 늘어짐에 새로운 명백한 회귀는 보이지 않았으나 모든 애니메이션 프레임의 메시 충돌을 정량 검증한 것은 아닙니다.
- 390×844 DPR 1 휴게실 60프레임 샘플: 평균 16.57ms, p95 16.8ms, 약 70.5만 삼각형/150 draw calls.
- DPR 2(실제 렌더 780×1688): 평균 29.91ms, p95 50.1ms. 다른 로컬 검사와 병행한 PC 에뮬레이션 측정이므로 독립 성능 기준이나 휴대폰 FPS로 해석하면 안 됩니다.
- **실제 iPhone/Android 실기기 성능, 실서버의 두 기기 채팅·권한, 실제 광고·카카오 공유는 미검증**입니다.
